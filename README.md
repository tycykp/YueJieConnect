# 越界互联 · YueJie Connect

## 越界互联安装包

应用包名为 `io.github.yuejie.connect`，APK 文件使用 `yuejie-connect` 前缀。从旧包名迁移时，安装新版并在 LSPosed 中启用新模块及其作用域，然后在原厂界面重新配对。两端应使用同一版本。

## 原厂配对（已验证入口）

`0.7.1-native-direct`（versionCode 32）从原厂页面自动启动桥接。两台实机均从模块进程停止的状态出发，经双向原厂配对进入已连接状态。局域网访问由系统兼容机制提供。

1. 两台设备连接同一 Wi-Fi，安装并在 LSPosed 中启用同一版本。ColorOS 作用域包含 **设备快连（`com.heytap.accessory`）** 和设备互联。首次启用或更新后重启原厂进程以加载本版模块。
2. 打开小米的 **融合设备中心** 和 ColorOS 的 **与平板互联** 页面。局域网发现窗口为两分钟，超时后重新进入页面。
3. **小米主动连接**：在小米原厂列表点击 **一加 Ace 6** 卡片。ColorOS 出现原厂“允许本机连接 Xiaomi Pad 8 Pro？”窗口，点击 **允许**，等待原厂窗口显示 **连接成功**。
4. **ColorOS 主动连接**：在 **与平板互联 → 添加新设备** 中选择 **Xiaomi Pad 8 Pro**，再点击小米原厂列表中的 **一加 Ace 6** 卡片确认。ColorOS 完成连接后进入原厂设备详情页，显示电量和 **断开连接**。
5. ColorOS 原厂卡片内的 **断开连接** 会撤回两端会话。再次连接时重新进入上述页面，任选一个方向重新发起并完成对端确认。

小米端不添加配对页，点击原厂卡片即发起或确认本次连接；ColorOS 的发现、允许、取消和连接结果均使用原厂页面。对端未确认时不发布在线设备或交换完整设备资料，拒绝后不能继续连接；新会话不能复用旧确认。

本次验收范围是上述两台设备的 **双向原厂主动连接**，其他机型及其他原厂入口尚未验收。“连接成功”验证了加密会话与实际逻辑通道，投屏、文件传输、应用接力等业务是否可用仍以功能表为准。

原厂直连安装包为 `dist/yuejie-connect-0.7.1-native-direct-arm64-debug.apk`。本轮通过 23 项 Java 定向测试、原厂配对 DEX 签名检查、APK 检查及 Android Lint。冷启动记录在 `build/native-direct-device/`，较早的配对专项记录在 `build/native-pairing-device/`。

投屏专项验证：38 项 Java 测试、2 项 Rust 协议测试及 Android Lint 通过；真机截图、会话状态和录屏释放证据在本地 `build/screen-repair-live/`。独立关闭专项另通过 9 项桥接测试及真机验证，证据在 `build/screen-close-device/`。该轮安装包为 `dist/yuejie-connect-0.6.7-screen-close.apk`。

投屏期间，小米原厂设备卡片会显示 **“正在使用手机妙享桌面”**，点击该项关闭投屏，设备连接继续保持；关闭后恢复 **“打开手机妙享桌面”**，可直接重新打开。侧边收起仅隐藏窗口。

## 技术栈

- Hook 框架：libxposed API 102（`102.0.0`）。
- Android：Java 17、Android SDK 37、ARM64（`arm64-v8a`）。
- 原生核心：Rust（Edition 2021）、JNI（`jni 0.21.1`）。
- 序列化：Serde、serde_json。
- 通信与加密：TCP、Noise（snow）、X25519、SHA-256。
- 构建工具：Gradle 9.7.1、Android Gradle Plugin 9.4.1、Cargo、Android NDK 29.0.14206865。
